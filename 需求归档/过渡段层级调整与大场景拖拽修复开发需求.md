# 过渡段层级调整与大场景拖拽修复开发需求

## 背景

当前过渡段（transition）是大场景的一种类型（`large_scenes.scene_type='transition'`），用户反馈此设计不合理：
过渡段应作为小场景类型，不属于大场景层级。同时大场景拖拽排序存在 bug：拖到自身位置时仍调用移动接口。

## 现状分析

### 数据现状

生产数据库中现有 2 个 transition 类型的大场景：

| id | 章节 | 名称 | sort_order | 子小场景数 |
|----|------|------|-----------|-----------|
| 8bfeb2ff | 0c3ec75e | 绑架男方入场 | 1 | 0 |
| 3b45d1c7 | 11d56e2b | 绳子松开 | 1 | 0 |

两者都排在各自章节第一位，且无子小场景。

### 代码现状

- `large_scenes.scene_type` 字段：DDL 默认 'content'，Pydantic 校验 `Literal["content", "transition"]`
- `small_scenes.scene_type` 字段：已存在，同样支持 content/transition
- 前端：新建/编辑大场景模态框有"内容段/过渡段"选择器；列表卡片有徽标
- 编译器：仅读取 scene_type 做数据传递，无 transition 特殊逻辑
- 数据库迁移机制：`schema_migrations` 版本表 + 幂等迁移函数

## 需求1：过渡段层级调整

### 方案

1. **数据迁移**：现有 `large_scenes.scene_type='transition'` 的记录转为 `small_scenes`（scene_type='transition'），挂到同章节第一个 `scene_type='content'` 的大场景下作为第一个小场景（sort_order=1，原小场景顺序后移）。原 large_scene 记录删除。

2. **字段保留**：`large_scenes.scene_type` 字段保留，值固定为 'content'。前端移除选择器，后端创建/更新时强制 'content'。

3. **前端**：移除大场景新建/编辑弹窗的"内容段/过渡段"选择器、移除大场景卡片的类型徽标。

### 迁移规则

对每个 `large_scenes.scene_type='transition'` 的记录 T：
1. 查找同章节中 `scene_type='content'` 且 `sort_order` 最小的 large_scene 作为目标 G
2. 若 G 不存在，将 T 的 scene_type 改为 content（无法迁移时回退为普通内容段）
3. 若 G 存在：
   - 在 G 下创建 small_scene，scene_type='transition'，name=T.name，sort_order=1
   - G 下原有 small_scenes 的 sort_order 全部 +1
   - 删除 T 这条 large_scene 记录
   - T 所在章节的其余 large_scenes 的 sort_order 在 T 之后的全部 -1

### 后端改动

- `database.py`：新增迁移版本 `v0.10.0`，函数 `_migrate_transition_large_scenes_to_small`
- `app_factory.py`：
  - `CreateLargeSceneRequest.scene_type` 移除 transition（值固定 content）
  - `UpdateLargeSceneRequest.scene_type` 移除 transition
  - 创建/更新大场景 API 忽略 scene_type 参数，固定 'content'
- `database.py` manager 层 `create_large_scene`/`update_large_scene`：校验 scene_type 只接受 content

### 前端改动

- `runtime-api.js`：
  - `ensureLargeSceneModal()`：移除 scene_type select
  - `openLargeSceneEditModal()`：移除 scene_type select
  - `largeSceneBlock()`：移除徽标 HTML、移除 scene-type CSS 类
  - `storyLargeSceneWrapper()`：移除徽标
  - 上下文菜单 `typeLabel`：移除过渡段判断
- `styles.css`：移除 `.large-scene-type-badge`、`.scene-type-transition` 样式

## 需求2：修复大场景拖拽到自身的无效排序

### 问题

拖动大场景到自身位置时，前端仍调用 `POST /api/large-scenes/{id}/move` 接口，后端执行无意义的重排，前端显示"已移动"。

### 修复

- HTML5 拖拽 `initLargeSceneDrag`：drop 事件中，若目标位置等于源位置（同 chapter + 同 sort_order），直接 return，不调用 move 接口
- Pointer 拖拽 `initLargeScenePointerDrag`：pointerup 中 `commitLargeScenePointerMove` 同样判断
- 拖动指示器渲染时排除被拖动项本身（不在被拖动项上方显示插入指示器）

## 验收标准

1. 数据迁移后，原 2 个 transition 大场景不再存在，对应章节的 large_scenes 全部为 content
2. 迁移后的小场景在目标大场景下作为第一个小场景，scene_type='transition'
3. 大场景新建/编辑弹窗无"内容段/过渡段"选择器
4. 大场景卡片无类型徽标
5. 拖拽大场景到自身位置不调用 move 接口、不刷新页面、不显示"已移动"

## 测试用例

1. 迁移脚本：执行后 `SELECT COUNT(*) FROM large_scenes WHERE scene_type='transition'` = 0
2. 迁移后：原"绑架男方入场"变为"主动前戏"下的第一个小场景（scene_type='transition'）
3. 拖拽：拖动大场景到自身位置，无网络请求、无 toast、无页面刷新
4. 拖拽：拖动大场景到其他位置仍正常工作

## 实际解决方案

### 后端实现

#### 1. 数据库迁移 v0.10.0

**文件**：`backend/app/database.py`

- 新增迁移注册：`_run_migration(connection, "v0.10.0", ...)`
- 新增迁移函数 `_migrate_transition_large_scenes_to_small_scenes(self, connection)`：
  1. 查询所有 `large_scenes.scene_type='transition'` 记录
  2. 对每条记录，在同 chapter 内查找第一个 `scene_type='content'` 的大场景作为父级
  3. 若无 content 大场景：将 transition 大场景就地转为 content（避免数据丢失）
  4. 若有 content 大场景：
     - 名称冲突检查（同名时加序号"（2）"）
     - 父级下现有小场景 `sort_order + 1`
     - 新建 `small_scene`（scene_type='transition'，sort_order=1）
     - 删除原 transition 大场景（手动清理 branches 和 transitions 引用）
  5. 重排每个 chapter 内剩余大场景的 sort_order（1, 2, 3, ...）
  6. 兜底：所有 `large_scenes.scene_type` 改为 'content'
- **幂等性**：若已无 transition 大场景，仅执行兜底 scene_type='content' 修正

#### 2. 移除大场景 scene_type 的 transition 选项

**文件**：`backend/app/app_factory.py`

- `CreateLargeSceneRequest`：移除 `scene_type` 字段
- `UpdateLargeSceneRequest`：移除 `scene_type` 字段，更新 `at_least_one_field` 验证器
- `create_large_scene` API 端点：不再传递 `scene_type`
- `update_large_scene` API 端点：不再传递 `scene_type`

**文件**：`backend/app/database.py`

- `create_large_scene` manager 方法：校验改为 `scene_type not in ("content",)`
- `update_large_scene` manager 方法：校验改为 `scene_type not in ("content",)`

### 前端实现

#### 3. 移除大场景内容段/过渡段选择与徽标

**文件**：`design/ui-preview/runtime-api.js`

- `largeSceneBlock()`：移除 sceneType/typeLabel 变量、scene-type CSS 类、data-scene-type 属性、类型徽标 HTML
- 检查器渲染：移除 typeLabel 变量、场景类型 form-group
- `storyLargeSceneWrapper()`：移除 typeLabel 变量、scene-type CSS 类、data-scene-type 属性、类型徽标 HTML
- `ensureLargeSceneModal()`：移除 scene_type select
- `openLargeSceneModal()`：移除 select 引用
- `openLargeSceneEditModal()`：移除 typeSelect 引用和赋值
- `submitLargeSceneEdit()`：移除 typeSelect/sceneType，body 改为 `{ name }`
- `submitLargeScene()`：移除 select/sceneType，body 改为 `{ name }`

**文件**：`design/ui-preview/styles.css`

- 移除 `.large-scene-block.scene-type-transition` 样式
- 移除 `.large-scene-type-badge` 及其 `[data-scene-type]` 变体样式
- 移除 `.story-canvas-center-panel .story-block.scene-type-transition` 样式
- 移除 `.story-canvas-center-panel .large-scene-type-badge` 样式
- 移除 `.story-large-scene-wrapper.scene-type-transition` 样式
- 移除 `.story-large-scene-wrapper .large-scene-type-badge` 样式

#### 4. 修复大场景拖拽到自身的无效排序

**文件**：`design/ui-preview/runtime-api.js`

**HTML5 拖拽（initLargeSceneDrag）**：
- `dragstart`：从 `data-sort-order` 属性读取原始 sort_order，存入 `dragState.sourceSortOrder`
- `drop`：计算 targetSortOrder 后，检查 `sourceChapterId === targetChapterId && sourceSortOrder === targetSortOrder`，若成立直接 return（不调用 API、不刷新、不显示 toast）

**Pointer Events 拖拽（initLargeScenePointerDrag）**：
- `pointerdown`：从 `data-sort-order` 属性读取原始 sort_order，存入 `pointerLargeSceneDrag.sourceSortOrder`
- `commitLargeScenePointerMove()`：计算 targetSortOrder 后，检查 `sourceChapterId === targetChapterId && sourceSortOrder === targetSortOrder`，若成立直接 return

**拖动指示器排除被拖动项**（已有逻辑，确认正确）：
- HTML5 `dragover`：`!child.classList.contains("dragging")` 过滤被拖动项
- Pointer `updateLargeSceneDropIndicator`：`child !== draggedItem && !child.classList.contains("dragging")` 过滤被拖动项
