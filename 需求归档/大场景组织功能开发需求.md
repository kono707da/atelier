# Atelier 大场景组织功能开发需求

状态：已完成（v0.2.0，2026-07-28）
优先级：当前最高  
开发范围：后端、数据库、前端画布、自动化测试  

## 1. 目标

在现有“项目 → 章节 → 大场景”结构上，完成大场景的类型管理、规整排序和跨章节移动。

完成后，用户应当能够：

1. 将大场景标记为“内容段”或“过渡段”。
2. 在同一章节内拖动大场景调整顺序。
3. 将大场景拖到同一项目的其他章节。
4. 在编辑窗口中同时修改大场景名称、类型和所属章节。
5. 在空章节中直接接收拖入的大场景。
6. 移动后立即看到数据库中的真实顺序，不显示虚假演示状态。

## 2. 概念定义

Atelier 采用以下业务层级：

```text
项目
└─ 章节
   ├─ 大场景：内容段
   ├─ 大场景：过渡段
   └─ 后续再开发小场景和分镜页
```

- 章节：作品中的主要地点或剧情阶段，例如沙滩、浅水区、更衣区、海边小屋。
- 内容段：章节中的主要互动段。
- 过渡段：开场、内部衔接、章节间衔接或结尾收束。
- 大场景只能属于一个章节。
- 大场景只能在同一项目的章节之间移动，禁止跨项目移动。

## 4. 数据库改造

### 4.1 新增字段

为 `large_scenes` 增加：

```text
scene_type TEXT NOT NULL DEFAULT 'content'
```

合法值：

- `content`：内容段
- `transition`：过渡段

要求：

1. 新数据库建表语句直接包含该字段。
2. 已存在数据库使用安全迁移增加字段。
3. 迁移前必须通过 `PRAGMA table_info(large_scenes)` 判断字段是否存在。
4. 不得删除、重建或覆盖现有 `large_scenes` 数据。
5. 现有记录统一获得默认值 `content`，禁止根据名称自动猜测类型。
6. 所有大场景读取接口必须返回 `scene_type`。

### 4.2 排序规则

- `sort_order` 在每个章节内从 1 开始连续排列。
- 同一章节内移动后，所有记录必须重新编号为 `1..N`。
- 跨章节移动后，来源章节和目标章节都必须重新编号。
- 移入空章节时，目标顺序为 1。
- 目标位置小于 1 时按 1 处理；大于目标章节长度时追加到末尾。
- 移动、重排和重新编号必须在同一个 SQLite 事务中完成。
- 操作失败时必须完整回滚。

### 4.3 约束

- 保留 `UNIQUE(chapter_id, name)`。
- 如果目标章节已有同名大场景，移动失败并返回明确错误，原数据和顺序保持不变。
- 目标章节不存在时返回 404。
- 目标章节与原章节不属于同一项目时拒绝移动。

## 5. 后端接口

### 5.1 创建大场景

扩展现有接口：

```http
POST /api/chapters/{chapter_id}/large-scenes
```

请求：

```json
{
  "name": "沙滩椅互动",
  "scene_type": "content"
}
```

- `scene_type` 可省略，默认 `content`。
- 非法类型返回 422。

### 5.2 编辑大场景

改造现有接口：

```http
PATCH /api/large-scenes/{large_scene_id}
```

请求：

```json
{
  "name": "新的名称",
  "scene_type": "transition",
  "chapter_id": "目标章节 ID"
}
```

规则：

- 三个字段均可选，但至少提供一个。
- 只修改名称或类型时保持当前顺序。
- 通过编辑窗口修改所属章节时，默认追加到目标章节末尾。
- 修改所属章节同样必须校验同项目、同名冲突并重新整理两个章节的顺序。

### 5.3 拖动移动

新增接口：

```http
POST /api/large-scenes/{large_scene_id}/move
```

请求：

```json
{
  "target_chapter_id": "目标章节 ID",
  "target_sort_order": 2
}
```

响应必须返回：

```json
{
  "database_environment": "test",
  "large_scene": {},
  "source_chapter_id": "",
  "target_chapter_id": "",
  "source_items": [],
  "target_items": []
}
```

同章节移动时，`source_items` 和 `target_items` 可以返回同一份最终列表。

## 6. 前端交互

### 6.1 大场景类型

- 大场景卡片必须显示类型徽标：
  - 内容段
  - 过渡段
- 两种类型应有明显但克制的颜色区别。
- 保持当前明亮、圆润、简洁的苹果风格。

### 6.2 新建大场景

现有“新建大场景”窗口增加“类型”选择。

- 默认选择“内容段”。
- 每个章节仍只能显示一个“添加大场景”按钮。
- 禁止恢复“添加第一个大场景”按钮。

### 6.3 编辑大场景

将当前单一改名窗口升级为“大场景编辑”窗口，包含：

- 名称
- 类型
- 所属章节

保存后重新读取真实接口数据并重绘画布。

章节改名窗口保持现状，不得受到影响。

### 6.4 拖动排序与跨章节移动

- 大场景只能沿章节轨道拖动，不允许在画布上自由摆放。
- 使用明确的拖动把手，不能让“改名”“删除”按钮触发拖动。
- 拖动过程中显示目标插入位置。
- 空章节轨道必须是有效放置区域。
- 放置成功后调用移动接口，再重新读取真实数据。
- 接口失败时恢复原画布，并显示后端错误。
- 禁止仅在 DOM 中调整顺序而不写数据库。
- 删除确认、改名弹窗和横向滚动不能与拖动冲突。

### 6.5 可访问性

- 拖动把手必须有清晰的 `aria-label`。
- 大场景仍应支持非拖动方式修改所属章节，即编辑窗口中的章节选择。
- 键盘用户能够通过编辑窗口完成与跨章节拖动等价的操作。

## 7. 数据安全

1. 自动化测试只能使用临时目录数据库。
2. 测试代码不得导入会创建默认全局应用的 ASGI 入口。
3. 浏览器端到端测试只能使用 8111 测试服务。
4. 禁止在生产项目中创建、移动、改名或删除验收数据。
5. 开发前后必须记录生产数据库：
   - SHA256
   - 文件大小
   - 修改时间
   - 项目、章节、大场景 ID 与名称
6. 除安全增加 `scene_type` 字段及默认值外，不得改动生产业务数据。
7. 测试服务必须保持 `locked_environment = test`。

## 12. 实际解决方案与测试结果

### 开发信息

- 开发日期：2026-07-28

### 实际解决方案

#### 数据库层（backend/app/database.py）

1. `large_scenes` 建表语句新增 `scene_type TEXT NOT NULL DEFAULT 'content'` 字段。
2. 新增 `_migrate_large_scenes_scene_type()` 方法：用 `PRAGMA table_info(large_scenes)` 检测列是否存在，不存在则 `ALTER TABLE large_scenes ADD COLUMN scene_type TEXT NOT NULL DEFAULT 'content'`，已有数据自动填充 `content`。
3. `list_large_scenes` / `get_large_scene` / `create_large_scene` / `delete_large_scene` 的 SELECT/INSERT 语句全部适配 scene_type。
4. 新增 `update_large_scene()` 方法：支持 name/scene_type/chapter_id 三字段可选更新，跨章节移动时追加到目标章节末尾并重排两个章节，校验同项目约束与同名冲突。
5. `rename_large_scene()` 保留为向后兼容包装，内部调用 `update_large_scene(name=...)`。
6. 新增 `move_large_scene()` 方法：单事务内同/跨章节重排，越界位置钳制到首尾，同名冲突/跨项目拒绝，返回 source/target chapter id 与 items。
7. `delete_large_scene()` 删除后立即将剩余场景重新编号为 1..N。

#### 接口层（backend/app/app_factory.py）

1. `CreateLargeSceneRequest` 新增 `scene_type: Literal["content", "transition"] = "content"`。
2. 新增 `UpdateLargeSceneRequest`：三字段可选，`model_validator` 校验至少一个。
3. 新增 `MoveLargeSceneRequest`：`target_chapter_id` + `target_sort_order: int = Field(ge=1)`。
4. `PATCH /api/large-scenes/{id}` 路由从 `rename_large_scene` 改为 `update_large_scene`，404/409 区分返回。
5. 新增 `POST /api/large-scenes/{id}/move` 路由。
6. 新增 `GET /api/large-scenes/{id}` 路由（供前端编辑弹窗加载详情）。
7. 应用版本从 `0.1.7` 升到 `0.2.0`。

#### 前端层（design/ui-preview/）

1. `runtime-api.js`：
   - `largeSceneBlock()`：卡片新增 `scene-type-{type}` 类、`data-scene-type` 属性、`draggable="true"`、顶部 `.large-scene-drag-handle` 把手（aria-label="拖动大场景调整顺序或跨章节移动"）、`.large-scene-type-badge` 徽标。
   - `chapterBlock()`：`.large-scene-lane` / `.large-scene-track` / `.large-scene-empty` 添加 `data-drop-zone` 与 `data-chapter-id`。
   - 新建弹窗 `ensureLargeSceneModal()` / `openLargeSceneModal()` / `submitLargeScene()`：增加类型 select，请求 body 带 `scene_type`。
   - 新增编辑弹窗 `openLargeSceneEditModal()` / `closeLargeSceneEditModal()` / `submitLargeSceneEdit()`：加载场景详情 + 章节列表，三字段可改，仅当章节变化时传 chapter_id。
   - 右键菜单 "改名" 对 large-scene 重定向到 `openLargeSceneEditModal`。
   - 新增 `initLargeSceneDrag()`：dragstart/dragover/drop 事件，计算插入位置，虚线占位指示器，调用 /move 接口，失败恢复 + toast 提示。
   - ESC 键与 click 监听适配新弹窗。
2. `styles.css`：新增类型徽标（内容段蓝色 rgba(111,126,213,0.18)/#5463c4，过渡段灰色 rgba(144,152,168,0.18)/#6b7280）、拖动把手（顶部 6px 横纹，点阵渐变，grab 光标）、拖动中状态、虚线占位框样式。
3. `index.html`：静态资源版本号更新为 `v=20260728-large-scene-organize`。
