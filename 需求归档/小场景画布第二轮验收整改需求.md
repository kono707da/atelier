## 4. 必须修复：项目剧本树

接口：

```http
GET /api/projects/{project_id}/story-tree
```

### 4.1 小场景必须返回的字段

每个 `small_scene` 必须至少包含：

```json
{
  "id": "small-scene-id",
  "large_scene_id": "large-scene-id",
  "name": "小场景名称",
  "scene_type": "content",
  "description": "",
  "sort_order": 1,
  "page_count": 10,
  "resource_count": 2,
  "pages": [],
  "resources": []
}
```

### 4.2 `resources` 字段

每个关联素材必须包含：

```json
{
  "link_id": "link-id",
  "material_id": "material-id",
  "name": "素材名称",
  "material_type": "expression",
  "sort_order": 1,
  "page_count": 4,
  "pages": [
    {
      "id": "material-page-id",
      "material_id": "material-id",
      "name": "素材页名称",
      "description": "",
      "sort_order": 1
    }
  ]
}
```

### 4.3 查询要求

- 必须按 `sort_order ASC` 返回章节、大场景、小场景、场景页、关联素材和素材页。
- 使用批量查询组装结果。
- 不允许对每个章节、大场景或小场景逐条建立连接并查询。
- `page_count` 必须等于 `pages.length`。
- `resource_count` 必须等于 `resources.length`。
- 没有数据时返回空数组和数字 `0`，不得省略字段或返回 `null`。

### 4.4 前端结果

素材关联成功后返回项目结构：

- 左侧“关联素材”数量必须立即正确。
- 左侧必须显示关联素材及其素材页数量。
- 中间画布的小场景卡片必须显示正确关联素材数量。
- 刷新后数量保持一致。

## 5. 必须修复：素材页映射的关联校验

接口：

```http
PUT /api/small-scene-pages/{scene_page_id}/mappings/{material_type}
```

设置映射前必须在同一事务中完成以下校验：

1. 场景页存在。
2. 场景页是小场景直属页，不是其他层级的错误页面。
3. 素材页存在。
4. 素材页所属素材存在。
5. 素材真实类型与 URL 中的 `material_type` 一致。
6. 素材已经通过 `small_scene_materials` 关联到该场景页所属的小场景。
7. 同一场景页、同一素材类型最多保留一个映射。

未关联素材的素材页不得映射，返回：

```http
422 Unprocessable Entity
```

建议错误信息：

```json
{
  "detail": "该素材尚未关联到场景页所属的小场景"
}
```

不得因为素材类型正确就跳过小场景关联校验。

## 6. 必须修复：移除素材关联

接口：

```http
DELETE /api/small-scene-resource-links/{link_id}
```

必须在一个数据库事务内完成：

1. 根据 `link_id` 找到 `small_scene_id` 和 `material_id`。
2. 找到该小场景的全部直属场景页。
3. 删除这些场景页中引用该素材任意素材页的全部映射。
4. 删除 `small_scene_materials` 关联行。
5. 保留素材。
6. 保留素材页。

禁止仅删除关联行而留下页面映射。

成功返回：

```json
{
  "database_environment": "production",
  "deleted": {
    "link_id": "link-id",
    "small_scene_id": "small-scene-id",
    "material_id": "material-id",
    "deleted_mapping_count": 2
  }
}
```

移除完成后：

- `workspace.resources` 不再包含该素材。
- `workspace.mappings` 不再包含该素材的映射。
- 场景页不得显示“素材 · 未命名页”。
- 素材库中原素材和素材页仍然存在。

## 7. 必须修复：场景页排序

接口：

```http
PUT /api/small-scenes/{small_scene_id}/pages/order
```

请求：

```json
{
  "page_ids": [
    "page-id-2",
    "page-id-1",
    "page-id-3"
  ]
}
```

### 7.1 完整集合校验

`page_ids` 必须与该小场景全部直属场景页 ID 集合完全一致。

以下请求全部返回 `422`：

- 缺少任意页面 ID。
- 同一页面 ID 重复出现。
- 包含其他小场景的页面 ID。
- 包含分支页面 ID。
- 包含不存在的页面 ID。
- 空数组。

### 7.2 单事务排序

- 排序校验和全部 `sort_order` 更新必须在一个事务中完成。
- 任意校验或写入失败时，原顺序必须完整保留。
- 不得在路由中循环调用每次独立提交的 `move_shot_page`。
- 排序成功后，`sort_order` 必须从 1 开始连续递增。

成功返回：

```json
{
  "database_environment": "production",
  "small_scene_id": "small-scene-id",
  "pages": []
}
```

## 8. 必须修复：API 状态码与返回结构

以下契约作为唯一标准。

### 8.1 创建场景页

```http

```

```json

  "page": {
    "id": "page-id",
    "small_scene_id": "small-scene-id",
    "name": "第 1 页",
    "description": "",
    "sort_order": 1
  }
}
```

### 8.2 修改场景页

```http
PATCH /api/small-scene-pages/{page_id}
```

成功状态码：`200`

```json
{
  "database_environment": "production",
  "page": {}
}
```

### 8.3 关联素材

```http
POST /api/small-scenes/{small_scene_id}/resources
```

成功状态码：`201`

```json
{
  "database_environment": "production",
  "resource": {
    "link_id": "link-id",
    "material_id": "material-id",
    "name": "素材名称",
    "material_type": "expression",
    "pages": []
  }
}
```

同一素材重复关联返回 `409`。

### 8.4 设置映射

成功状态码：`200`

```json
{
  "database_environment": "production",
  "mapping": {
    "id": "mapping-id",
    "scene_page_id": "scene-page-id",
    "material_page_id": "material-page-id",
    "material_type": "expression"
  }
}
```

### 8.5 取消映射

同一个 `PUT` 接口必须支持：

```json
{
  "material_page_id": null
}
```

成功返回：

```json
{
  "database_environment": "production",
  "mapping": null
}
```

现有 `DELETE` 取消接口可以保留兼容，但前端和测试必须以 `PUT + null` 的唯一契约为准。

### 8.6 前端兼容

修改返回结构后，必须同步检查 `runtime-api.js`。

页面不得因为从平铺结果改为 `page`、`resource`、`mapping` 包裹而失效。

## 17. 实际解决方案

分支：`dev-260729-GLM5.2-小场景第二轮整改`（从 `GLM-MAIN` 拉取新建）
日期：2026-07-29

### 17.1 story-tree 返回完整字段（修复失败项 1、2）

- 每个 `resource.pages` 项包含 `id`、`material_id`、`name`、`description`、`sort_order`。
- 新增为每个 resource 计算 `page_count` 字段。
- 使用批量查询（IN 子句）避免 N+1。

### 17.2 映射关联校验（修复失败项 3、5）

- `set_small_scene_page_mapping` 在设置映射前依次校验：
  1. 场景页存在
  2. 素材页存在
  3. 素材存在
  4. 素材真实类型与 URL 中的 `material_type` 一致
  5. 素材已通过 `small_scene_materials` 关联到该场景页所属小场景
- 未关联返回 422，错误信息："该素材尚未关联到此小场景，不能设置映射"。
- 跨小场景关联返回 422。
- 类型不一致返回 422。

### 17.3 移除关联级联删除映射（修复失败项 4、5）

- `remove_small_scene_resource_link` 在单事务内：
  1. 根据 `link_id` 找到 `small_scene_id` 和 `material_id`
  2. 找到该素材的全部 `material_pages`
  3. 删除该小场景直属场景页中引用这些 `material_pages` 的全部映射
  4. 删除 `small_scene_materials` 关联行
  5. 保留素材和素材页
- 返回 `deleted_mapping_count` 字段。
- 不删除同一素材在其他小场景的映射。

### 17.4 场景页排序单事务 + 完整集合校验（修复失败项 6、7）

- 新增 `reorder_scene_pages` 数据库方法，单事务完成排序。
- 校验 `page_ids` 与该小场景直属场景页 ID 集合完全一致：
  - 缺失 ID → 422
  - 重复 ID → 422
  - 跨小场景 ID → 422
  - 分支页面 ID → 422
  - 不存在 ID → 422
  - 空数组 → 422
- 校验或写入失败时原顺序完整保留（单事务回滚）。
- 成功后 `sort_order` 从 1 开始连续递增。
- 路由层不再循环调用 `move_shot_page`，直接调用 `reorder_scene_pages`。

### 17.5 API 状态码与返回结构（修复失败项 8）

- 创建场景页 `POST /api/small-scenes/{id}/pages` → 201 + `{"page": {...}}`
- 修改场景页 `PATCH /api/small-scene-pages/{id}` → 200 + `{"page": {...}}`
- 关联素材 `POST /api/small-scenes/{id}/resources` → 201 + `{"resource": {link_id, material_id, name, material_type, pages}}`
- 重复关联 → 409
- 设置映射 `PUT /api/small-scene-pages/{id}/mappings/{type}` → 200 + `{"mapping": {...}}`
- 取消映射 `PUT .../mappings/{type}` + `{"material_page_id": null}` → 200 + `{"mapping": null}`
- 移除关联 `DELETE /api/small-scene-resource-links/{id}` → 200 + `{"deleted": {link_id, small_scene_id, material_id, deleted_mapping_count}}`

### 17.6 PUT null 取消映射（修复失败项 9）

- `SetMappingRequest.material_page_id` 改为 `str | None`，允许 `null`。
- `set_small_scene_page_mapping` 在 `material_page_id is None` 时调用 `unset_small_scene_page_mapping` 并返回 `None`。
- 路由层根据返回 `None` 输出 `{"mapping": null}`。
- 旧 `DELETE` 接口保留兼容，但前端已改为 `PUT + null`。

### 17.7 旧接口差量更新保留 id（修复失败项 10）

- `set_small_scene_materials` 重写为差量更新：
  - 仍保留的素材关联保留原 `id`（link_id）
  - 新增素材关联生成新 UUID
  - 被移除素材的相关页面映射一并删除（仅限当前小场景）
  - 最后重新写入连续 `sort_order`
  - 全部在单事务内完成

### 17.8 历史 空 id 迁移修复

- 新增 `_migrate_fix_empty_link_ids` 迁移方法：
  - 查找 `small_scene_materials.id IS NULL OR id = ''` 的行
  - 为每行生成唯一 UUID
  - 重复初始化不修改已有有效 ID
- 在 `initialize` 中调用，紧跟 `_migrate_default_material_pages` 之后。
