## 5. 数据字段

### 5.1 用户字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `name` | string | 必填，1–80 字，去除首尾空白 |
| `material_type` | string | 必填，六种固定值之一 |
| `description` | string | 默认空，最多 300 字 |
| `content` | string | 必填，非空，最多 50,000 字 |
| `prompt_text` | string | 默认空，最多 50,000 字 |
| `negative_prompt` | string | 默认空，最多 20,000 字 |
| `validation_status` | string | `unverified` 或 `verified`，默认 `unverified` |
| `notes` | string | 默认空，最多 5,000 字 |
| `tags` | string[] | 最多 30 个，单个标签 1–40 字 |

### 5.2 系统字段

- `id`：UUID 字符串。
- `created_at`：UTC ISO 8601。
- `updated_at`：UTC ISO 8601。
- `preview_url`：原图接口地址或 `null`。
- `thumbnail_url`：缩略图接口地址或 `null`。

### 5.3 重名规则

- 同一素材类型内名称忽略大小写唯一。
- 不同类型允许同名。
- 冲突返回 `409`。

## 6. 数据库设计

沿用 `DatabaseManager` 当前激活的 SQLite 数据库，不新建独立素材数据库。

### 6.1 `materials`

```sql
CREATE TABLE IF NOT EXISTS materials (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL COLLATE NOCASE,
    material_type TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    content TEXT NOT NULL,
    prompt_text TEXT NOT NULL DEFAULT '',
    negative_prompt TEXT NOT NULL DEFAULT '',
    validation_status TEXT NOT NULL DEFAULT 'unverified',
    notes TEXT NOT NULL DEFAULT '',
    preview_original_path TEXT,
    preview_thumbnail_path TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE (material_type, name),
    CHECK (
        material_type IN (
            'composition',
            'expression',
            'scene',
            'lighting',
            'prompt',
            'composite_template'
        )
    ),
    CHECK (validation_status IN ('unverified', 'verified'))
);

CREATE INDEX IF NOT EXISTS idx_materials_type_updated
    ON materials(material_type, updated_at DESC);

CREATE INDEX IF NOT EXISTS idx_materials_status_updated
    ON materials(validation_status, updated_at DESC);

CREATE INDEX IF NOT EXISTS idx_materials_name
    ON materials(name);
```

### 6.2 `material_tags`

```sql
CREATE TABLE IF NOT EXISTS material_tags (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL COLLATE NOCASE UNIQUE,
    created_at TEXT NOT NULL
);
```

### 6.3 `material_tag_links`

```sql
CREATE TABLE IF NOT EXISTS material_tag_links (
    material_id TEXT NOT NULL,
    tag_id TEXT NOT NULL,
    created_at TEXT NOT NULL,
    PRIMARY KEY (material_id, tag_id),
    FOREIGN KEY (material_id)
        REFERENCES materials(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id)
        REFERENCES material_tags(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_material_tag_links_tag
    ON material_tag_links(tag_id, material_id);
```

### 6.4 标签规则

- 标签必须进入标签表和关联表，禁止只保存逗号字符串。
- 去除首尾空白，忽略大小写去重。
- 创建/更新素材和标签关联必须在同一事务。
- 更新请求中的 `tags` 表示完整替换。
- 本期不要求自动删除孤立标签。

## 15. 预览图接口

### 15.1 存储

```text

```

数据库只保存相对数据根目录的路径，禁止保存 BLOB 和任意绝对路径。

### 15.2 上传

```http
POST /api/materials/{material_id}/preview
Content-Type: multipart/form-data
```

字段：`file`

支持：

- JPG
- PNG
- WebP

限制：

- 文件最大 20 MB。
- 必须按文件内容解码，不能只信任扩展名或 MIME。
- 解码后最长边不得超过 16,384 像素。
- 使用 Pillow 生成最长边 512 像素的 WebP 缩略图，质量建议 82。
- 在新文件完整写入并验证成功后再替换旧文件。
- 上传失败必须保留旧图。

成功：

```json
{
  "database_environment": "production",
  "preview_url": "/api/materials/uuid/preview",
  "thumbnail_url": "/api/materials/uuid/thumbnail"
}
```

### 15.3 删除

```http
DELETE /api/materials/{material_id}/preview
```

只删除预览文件并清空路径，不删除素材。

### 15.4 读取

```http
GET /api/materials/{material_id}/preview
GET /api/materials/{material_id}/thumbnail
```

要求：

- 正确设置 `Content-Type`。
- 提供合理浏览器缓存头。
- 文件不存在返回 `404`。
- 安全解析路径，禁止路径穿越。

## 21. 实际解决方案

### 21.1 数据库层

沿用 `DatabaseManager` 当前激活 SQLite 数据库（保持 WAL 模式不改），新增三表：

- `materials`：含 `UNIQUE(material_type, name)` 同类型内名称唯一约束、`material_type` 与 `validation_status` CHECK 约束、三个索引（类型+更新时间、状态+更新时间、名称）。`preview_original_path` / `preview_thumbnail_path` 存储相对 `data_root` 的相对路径，不保存 BLOB 或绝对路径。
- `material_tags`：`name` 使用 `COLLATE NOCASE UNIQUE`。
- `material_tag_links`：`material_id` + `tag_id` 复合主键，双向 `ON DELETE CASCADE`，`tag_id, material_id` 索引。

### 21.2 数据访问层

在 `DatabaseManager` 新增 7 个方法：

- `list_materials`：SQL 层完成搜索（name/description/content/tag 四字段 LIKE，转义 `%`/`_`/`\`）、类型/状态/标签精确筛选、四种排序、分页，一次 JOIN 聚合返回标签列表避免 N+1。列表项不含 `content`/`prompt_text`/`negative_prompt`/`notes`/`preview_url`。
- `get_material`：返回完整字段 + 标签列表 + `preview_url`/`thumbnail_url`。
- `create_material`：单事务创建素材 + 标签关联，忽略大小写去重。
- `update_material`：区分字段未提交与明确清空，`tags` 为完整替换，单事务。
- `delete_material`：级联清理标签关联与 `data/materials/{material_id}` 图片目录，路径钳制防止越权删除。
- `list_material_tags`：按引用数降序、名称升序，服务端上限 100。
- `set_material_preview_paths`：更新预览图路径字段。

### 21.3 接口层

新增 9 个路由，Pydantic 模型带字段级校验，错误响应返回用户可读中文，不暴露 SQLite 错误或绝对路径：

- `GET /api/materials`：列表查询。
- `POST /api/materials`：新建素材，成功 201。
- `GET /api/materials/{material_id}`：详情，不存在 404。
- `PATCH /api/materials/{material_id}`：局部更新，至少一个字段否则 422，重名 409。
- `DELETE /api/materials/{material_id}`：删除素材并清理图片目录。
- `GET /api/material-tags`：标签候选。
- `POST /api/materials/{material_id}/preview`：上传预览图。
- `DELETE /api/materials/{material_id}/preview`：删除预览图。
- `GET /api/materials/{material_id}/preview` / `GET /api/materials/{material_id}/thumbnail`：读取图片，显式映射扩展名到 MIME 类型。

### 21.4 图片处理

Pillow 按文件内容解码校验（不信任扩展名/MIME），20MB 上限，最长边 16384 像素上限，生成 512px WebP 缩略图（质量 82），先写临时文件再原子替换，上传失败保留旧图。

### 21.5 依赖

`requirements.txt` 新增 `Pillow==12.3.0`、`python-multipart==0.0.32`。
